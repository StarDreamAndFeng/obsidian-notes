# Obsidian 笔记整理与入库

把零散内容（草稿、剪藏、对话记录、流水账）整理为符合本库规范的正式笔记，并确保它通过双向链接接入现有知识网络。

## 规范来源（按需读取，不要一次全读）

- 根目录 `README.md`：仓库 MECE 目录地图、命名与使用约定。
- `500-资源整合/540-工具与软件/笔记整理工作流指南.md`：语言规范化与结构化原则（本 skill 的上位规范）。
- `references/vault-map.md`：内容归类决策表与当前真实目录。
- `assets/note-template.md`：标准成稿模板，整理时照此骨架组织。
- `assets/weekly-report-template.md`：周报/复盘类模板，按需生成时使用。

若用户的明确指令与上述规范冲突，以用户指令为准，并在汇报中说明偏离点。

## 工作流

### 1. 读原稿，盘点素材

1. 读取用户指定文件全文；用 LS/Glob 核对文中引用的图片是否真实存在于 `/000-仓库管理/020-附件与资源/`。
2. 判断内容是否完整可归档：内容残缺、明显未写完的，留在 `000-仓库管理/030-草稿/` 只做规范化；已成稿的，按 `references/vault-map.md` 确定正式目录。
3. 归档（移动/重命名）属于较大改动：用户未明确指示目标位置时，先给出建议路径再动手。

### 2. 文件命名

- 用简洁达意的中文主题名，与文内 H1 对应，让读者只看文件名就知道内容，例如 `Apache Maven安装指南.md`、`Git Stash临时暂存机制.md`。
- 禁止：以 `.` 开头（会被 Obsidian 隐藏）；包含 `/ \ * ? " < > |` 及 `]]`。
- 可加领域前缀消歧，如 `Rust踩坑-getrandom...md`；日记用 `YYYY-MM-DD`；周报用 `YYYY-WNN-周报.md`（如 `2026-W38-周报.md`）。
- 草稿目录下的 `1.md`、`未命名.md` `草稿.md` 这类临时名，整理后必须改名。

### 3. 正文规范化

依据《笔记整理工作流指南》四原则执行：

1. **剔除口语化**：删除问候语、"好。""那么"等口头禅、第一人称流水账，改写为客观书面语；技术信息一条不丢。
2. **结构化**：H1 标题 → `## 概述` → 若干分节，章节间用 `---` 分隔；操作步骤用有序列表，并列信息用表格，命令/路径/按键用行内代码或代码块。
3. **修正文字**：错别字、语病、标点（中英文之间留空格的风格不强求，但同一篇内要统一）。
4. **图片**：
   - 一律用 vault 绝对路径：`![中文说明](/000-仓库管理/020-附件与资源/xxx.png)`。
   - alt 写清图片用途，不要留 `image-2026...` 式无意义描述。
   - 附件夹中存在但未引用、且明显对应该文步骤的图片，可补到正确位置；无法确认归属的不要硬塞。

### 4. 补 YAML frontmatter

```yaml
---
tags:
  - 标签1
  - 标签2
date: YYYY-MM-DD
---
```

- **`date` 永远填执行整理动作的当日日期**，与正文里出现的 `range` / `published` / 事件发生时间无关。
  - ❌ 错误示例：周报正文 `range: 2026-09-14 ~ 2026-09-20`，却把 `date` 写成 `2026-09-20`（这是 range 末尾日期）
  - ✅ 正确示例：同上场景，`date` 写成整理动作实际发生的当天（如 `2026-09-22`）
  - 区分：`date` = 笔记入库时间（笔记库视角），`published` = 原文发布时间（剪藏视角），`range` = 周报覆盖区间（业务视角）
- 周报类笔记加 `week`（ISO 周编号，如 `2026-W38`）和 `range`（覆盖区间）字段。
- 剪藏文章再加 `source`（原文 URL）和 `author`；GitHub 项目相关再加 `repo`。
- `tags` 用块级列表，用词向同目录相邻笔记看齐（先 Glob/Grep 同类笔记参考已有标签），2-6 个为宜；本库实际使用扁平中文标签（如 `环境配置`、`Git`），不要自造层级标签。

### 5. 双向链接入库检查（核心步骤，不可跳过）

目标：新笔记必须能链入现有网络，而不是成为孤岛。

1. **提炼关键词**：从成稿提取 5-10 个主题词（技术/工具/软件/概念名）。
2. **检索候选笔记**：对每个关键词用 Glob（`**/*关键词*.md`）匹配文件名，再用 Grep 检索标签与正文主题。
3. **核实链接目标存在**：候选链接必须用 Glob 确认库内确有同名 `.md`。链接写笔记名、不带 `.md`，如 `[[Apache Maven安装指南]]`。
4. **文末挂接**：在文末 `---` 之后写 `**关联笔记：**` 区块：
   - 只放真实相关、且文件存在的笔记，每条可附 ` - 一句话说明关系`。
   - 可挂已存在的目录索引/MOC 笔记。注意本库目前没有目录 MOC 文件，`[[351-Android开发]]` 这类指向文件夹的是红线链接——仅当该文确属该分类、且值得未来开坑建 MOC 时保留，每篇至多 1-2 个，并在汇报中列明。
   - 红线链接（目标不存在）宁缺毋滥；不准凭印象编造笔记名。
5. **正文内嵌链接**：正文中首次提到的核心概念，若库内已有同名笔记，改为行内 `[[笔记名]]`；普通名词不做链接堆砌。
6. **反向链接**：Obsidian 会自动生成反向链接，默认不改动旧文。若某篇强相关旧文的"关联笔记"区块明显应回链本文，只在汇报中建议，经用户同意后再补。

### 6. 归档移动

- 成稿从 `030-草稿` 移入正式目录时，用 PowerShell `Move-Item` 一步完成移动与改名。
- wiki 链接按笔记名解析、图片为绝对路径，vault 内移动不会断链，无需改正文。
- 不得改动 `.obsidian/`、`.git/`、`.trae/rules/`。

### 7. 交付前自检

- [ ] YAML 合法，`tags`、`date` 齐全；`date` = 整理动作当日（**不是**正文 `range`/`published`/事件日期）；周报有 `week`/`range`；剪藏有 `source`/`author`。
- [ ] 所有图片路径在附件夹中实际存在。
- [ ] 关联笔记逐条核实过文件存在（红线链接已单独列出理由）。
- [ ] 文件名合规、与 H1 对应；草稿临时名已消除。
- [ ] 无残留口语、空段落、草稿符号；技术步骤完整。
- [ ] 若发生移动：旧路径已不存在，新路径可打开。

### 8. 周报与复盘类笔记（按需生成）

适用于每周/每月复盘、知识库成长记录。**有产出才生成**——检索仓库现有笔记，按 `date` 字段判断该区间内是否有新归档内容：

| 区间内新归档笔记数 | 是否生成周报 |
| --- | --- |
| ≥ 1 篇 | ✅ 生成（按 `assets/weekly-report-template.md` 骨架） |
| 0 篇 | ❌ 不生成，保留空档而非硬凑 |

**生成要点：**
- `date` = 整理当日，与 `range` 无关
- `week` 用 ISO 周编号（`YYYY-WNN`，如 `2026-W38`）
- 按分类聚合笔记清单，每篇加一句话核心内容
- 「问题与反思」分三层：元数据 / 内容深度 / 工作流
- 末尾用表格量化本周数据

**归档位置：** 默认建议 `100-每日笔记/110-周报与月结/`（该分类尚未创建时询问用户）。

## 边界

- 只整理，不虚构：不编造来源链接、软件版本、命令输出或不存在的笔记。
- 不主动 `git commit`，除非用户明确要求；提交信息遵循 `.trae/rules/git-commit-message.md`。
- 不主动新建 MOC 索引文件；不批量改造其他笔记。
- 内容安全：对盗版/破解等内容仅做中立的文字格式整理，不补充获取渠道或扩写操作指引。
