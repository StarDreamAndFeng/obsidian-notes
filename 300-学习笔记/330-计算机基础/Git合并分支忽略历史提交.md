# Git 合并分支忽略历史提交

## 概述

在 Git 中，若需在合并分支时忽略或丢弃被合并分支上的所有历史提交信息，只保留最终代码的修改并生成一条全新的提交记录，最标准且最安全的方法是使用 `--squash` 参数。

---

## 方法一：使用 `git merge --squash`（最推荐）

`--squash` 的作用是：把被合并分支上的所有改动"压缩"到当前分支的暂存区，但不自动生成提交。这样可以自行编写一条全新的提交信息，原本分支上的提交历史完全不会被带过来。

### 操作步骤

假设当前在 `main` 分支，想要合并 `feature` 分支，但不保留 `feature` 上的提交记录：

```bash
# 1. 切换到目标分支（如 main）
git checkout main

# 2. 执行 squash 合并
git merge --squash feature

# 3. 查看暂存区状态，确认 feature 的代码改动已在暂存区
git status

# 4. 提交代码，编写自定义提交信息
git commit -m "feat: 完成了某功能（合并了 feature 分支的代码，但不保留其历史提交）"
```

### 结果

在 `git log` 中，仅会看到 `main` 分支上多出一条全新的 commit，`feature` 分支上之前的 `fix bug`、`update`、`add file` 等中间提交记录全部被隐藏。

---

## 方法二：使用变基并压缩

若习惯保持线性的提交历史，可在合并前先到被合并的分支上把历史压缩成一条，然后再合并。

### 操作步骤

```bash
# 1. 切换到被合并的分支
git checkout feature

# 2. 查看该分支有多少个提交（假设有 4 个提交）
git log

# 3. 执行交互式变基（HEAD~4 表示合并最近的 4 个提交，数字根据实际情况调整）
git rebase -i HEAD~4

# 4. 文本编辑器打开后，将除第一行之外的 `pick` 全部改成 `s`（代表 squash）：
#   pick 1234567 第一个提交
#   s 89abcde 第二个提交
#   s def1234 第三个提交
#   s 5678abc 第四个提交
# 保存并关闭编辑器。

# 5. 弹出另一个编辑器用于编写合并后的新提交信息，修改后保存关闭。

# 6. 切回主分支并进行快进合并
git checkout main
git merge feature
```

### 结果

`feature` 分支本身只剩一条记录，合并到 `main` 后自然也就只有一条记录。

---

## 补充：撤销已执行的普通合并

若已执行普通的 `git merge feature`，发现提交历史被带过来，且尚未 push 到远程，可使用以下命令撤销这次合并：

```bash
# 撤销合并，保留工作区和暂存区的修改
git reset --soft HEAD~1

# 重新按照方法一使用 --squash 来合并
```

---

## 方法对比

| 方法 | 特点 | 推荐度 |
|------|------|--------|
| `git merge --squash` | 不改变已有分支历史，操作安全，直接生成一条新提交 | ⭐⭐⭐ |
| `git rebase -i` | 需要修改 feature 分支历史，保持线性提交记录 | ⭐⭐ |

---

## 总结建议

绝大多数情况下，`git merge --squash` 是最简单、最不容易出错的方式。它不会改变已有分支的历史（相比于 rebase 更安全），同时完美实现了"只要代码，不要历史提交信息"的需求。
