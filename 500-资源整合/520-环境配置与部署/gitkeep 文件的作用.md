# `.gitkeep` 文件的作用

## 核心原理

**Git 不跟踪空目录**——这是 Git 的设计原则，它只跟踪文件，不跟踪目录本身。一个目录只有在包含至少一个被 Git 跟踪的文件时，才会被记录下来。

## `.gitkeep` 的作用

`.gitkeep` 是一个**约定俗成的占位文件**，用于让 Git 能够跟踪和保存空目录。

### 命名约定

`gitkeep` **不是** Git 的官方特性，只是社区约定的文件名。你也可以用其他名字（如 `placeholder`、`.keep`），但 `.gitkeep` 是最常见的选择。

## 使用场景

```
学习笔记/      ← 空目录，Git 不会跟踪
  └── .gitkeep  ← 放入这个文件后，Git 会跟踪这个目录
```

### 典型用途

1. **初始化目录结构**：在项目初期创建目录框架，便于团队协作和项目规划
2. **占位等待内容**：预先创建目录，后续再添加实际内容
3. **同步目录结构**：确保远程仓库包含完整的目录层级

## 实践建议

### 何时使用

- 需要在仓库中保留一个空目录时
- README 文档中声明了目录结构时
- 需要多设备同步目录框架时

### 何时删除

当目录中已经有实际内容（如笔记文件、代码文件）后，`.gitkeep` 文件可以保留或删除，因为目录已经不再是空的了。

### 替代方案

除了 `.gitkeep`，还可以：

- 在目录中放一个 `README.md` 说明文件
- 直接放入第一个实际文件
- 使用 `.gitignore` 的技巧（不太推荐）

## 示例

```bash
# 创建目录并添加 .gitkeep
mkdir -p 学习笔记/工作记录
touch 学习笔记/.gitkeep
touch 工作记录/.gitkeep

# 提交到 Git
git add 学习笔记/.gitkeep 工作记录/.gitkeep
git commit -m "chore: init directory structure"
```
