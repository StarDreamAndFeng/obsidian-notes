# obsidian-notes

个人 Obsidian 知识库笔记仓库，集中存放日常学习、工作记录、想法随笔与资源整合。

## 特点

- **纯 Markdown 格式**：所有笔记采用标准 Markdown 编写，便于跨平台阅读与编辑
- **Obsidian 原生特性支持**：
  - 双向链接（`[[笔记名称]]`）
  - 内部引用
  - 标签管理（`#标签`）
- **版本控制**：通过 Git 追踪所有笔记版本，支持多设备同步、备份与历史回溯
- **MECE 分类结构**：顶层遵循相互独立、完全穷尽原则，底层按技术栈/业务线展开

## 结构设计说明（MECE 视角）

顶层 7 个文件夹完全符合 MECE 法则，互不交叉且覆盖技术工作者的所有场景：

### 000-仓库管理（系统与元数据）

定位：不包含业务知识，只存放维持 Obsidian 运行的系统文件。

- `010-模板`：存放笔记模板（如每日笔记模板、技术方案模板）
- `020-附件与资源`：存放图片、PDF 等。可在 Obsidian 设置中将附件默认路径指向此文件夹。

### 100-每日笔记（时间流记录）

定位：按时间维度组织的零碎记录，与知识维度组织的文件夹相互独立。

- 配合 Obsidian 核心插件"日记"使用，日期格式 `YYYY-MM-DD`
- `110-周报与月结`：定期汇总，避免每日笔记沦为无法检索的信息垃圾

### 200-工作记录（产出与行动导向）

定位：工作产出内容，强目标导向。

- `210-项目与需求`：按端拆分为前端项目（JS为主）和后端项目（Java为主）
- `220-技术方案与架构`：脱离具体项目的通用架构设计、数据库设计文档
- `230-会议与沟通`：需求评审、技术对齐会议记录
- `240-工作复盘与排期`：Bug 复盘、里程碑排期等

### 300-学习笔记（知识体系导向）

定位：个人知识沉淀，与工作产出分离。

- `310-前端技术栈`：JS 基础、框架、样式
- `320-后端技术栈`：Java 基础、Spring、数据库与中间件（Redis/MQ等）
- `330-计算机基础`：网络、操作系统、数据结构等内功
- `340-阅读笔记`：技术书籍、源码解析笔记
- `350-移动端技术栈`：移动端开发学习
  - `351-Android开发`：Android 原生开发、Kotlin、Jetpack 等
  - `352-iOS开发`：iOS 原生开发、Swift、UIKit/SwiftUI 等
  - `353-跨平台框架`：Flutter、React Native、UniApp 等

### 400-想法随笔（发散思维导向）

定位：非结构化的灵感与思考。

- `410-技术思考`：对技术趋势、架构设计的深度思考
- `420-生活与感悟`：生活记录、个人成长感悟

### 500-资源整合（外脑与工具箱）

定位：外部资源与工具集合，拿来即用。

- `510-代码片段`：常用工具函数、正则表达式等（建议用代码块语言标注）
- `520-环境配置与部署`：Nginx 配置、Docker 命令、CI/CD 脚本等
- `530-优质文章剪藏`：网页剪藏内容
- `540-工具与软件`：软件推荐、插件使用说明等

### 600-生活与娱乐（个人生活记录）

定位：工作学习之外的个人生活与文娱活动记录。

- `610-影音记录`：电影观后感、剧集追踪、视频学习/收藏记录
- `620-游戏与电竞`：游戏攻略、游戏评测、游玩记录
- `630-读物与小说`：非技术类书籍、网文小说的阅读笔记与摘录
- `640-生活日常与消费`：旅行计划、大额消费记录、生活清单

## 最佳实践建议

### 文件命名规范

- 每日笔记：`2023-10-25_周三`
- 技术方案：`2023-10-25_用户登录态重构方案`
- 代码片段：`SNIPPET_JS_防抖节流`

### 用标签代替子文件夹

控制层级深度不超过 3 层，在底层使用标签分类。例如在 `311-JavaScript核心` 下，直接建笔记并打上 `#js/闭包`、`#js/原型链` 等标签。Obsidian 中标签比深层文件夹更好用。

在 `600-生活与娱乐` 中同样适用：不要在 `610-影音记录` 里再建"电影"、"电视剧"文件夹，而是直接建笔记并打上 `#电影`、`#科幻` 等标签。

### 利用 MOC（Map of Content）索引

在每个二级文件夹中创建同名笔记文件，用 `[[双链]]` 串联重要笔记，形成知识网络。

### 每日笔记作为收件箱

每天的零碎记录先全部扔进当日文件，周末回顾时再进行整理：
- 完整的技术方案 → 移动到 `200-工作记录`
- 好的灵感 → 移动到 `400-想法随笔`
- 值得学习的知识 → 整理到 `300-学习笔记`
- 娱乐消费记录 → 整理到 `600-生活与娱乐`

### 生活记录的颗粒度

不需要每一部看过的电影、玩过的游戏都写长篇大论。可以只在 `100-每日笔记` 里写一句简短记录。只有当需要认真写评测或记录攻略时，再单独建一篇笔记放进 `600-生活与娱乐` 中。

### 利用 Dataview 插件做追踪清单

对于电影、小说、游戏，可利用 Dataview 插件自动生成追踪表格。例如在 `610-影音记录` 里建一个主页笔记，添加 Dataview 查询：

```dataview
TABLE 评分, 观看日期
FROM "600-生活与娱乐/610-影音记录"
WHERE 类型 = "电影"
SORT 观看日期 DESC
```

这样就能拥有一个自动更新的私人观影单。
