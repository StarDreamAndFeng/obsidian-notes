# 个人金融桌面工具技术选型方案：Tauri 2.0 + Vue 3 + SQLCipher

## 概述

针对涉及加密存储、数据可视化的个人桌面工具场景，推荐采用 **Tauri 2.0 + Vue 3 + SQLCipher** 技术栈组合。该方案在包体体积、内存占用、加密安全性、启动速度等维度均表现优异。

---

## 技术栈对比分析

| 维度 | Tauri 2 + Vue3 + SQLite | Electron + Vue3 | Python + PySide6 |
|------|------------------------|-----------------|------------------|
| 安装包体积 | **~8-12 MB** | ~120-180 MB | ~60-100 MB |
| 内存占用 | **~30-50 MB** | ~150-300 MB | ~80-150 MB |
| 加密安全性 | **Rust AES-256-GCM 原生实现** | Node.js crypto（可行但进程暴露） | Python cryptography（可行） |
| 启动速度 | **< 1 秒** | 2-4 秒 | 1-2 秒 |
| 图表生态 | ECharts / Chart.js | 同左 | matplotlib（视觉效果一般）/ pyqtgraph（商务感不足） |
| 学习成本 | 中（需少量 Rust） | 低 | 低 |
| 打包分发 | 单文件 exe / dmg / deb | 同左 | 依赖环境，打包复杂度高 |

**选型结论**：涉及密码和资金账号存储场景时，Rust 后端在内存安全与加密原语方面的优势为决定性因素。Tauri 2 的 IPC 机制相比 Electron 更具安全性，前端 JavaScript 进程无法直接访问原始密钥。

### 模块二：密码管理

#### 数据表设计

```
┌────────────────────────────────┐
│ credentials                    │
├────────────────────────────────┤
│ id          INTEGER PK         │
│ title       TEXT  (如"光大证券") │
│ category    TEXT  (券商/银行/社交/其他) │
│ username    TEXT  (账号)        │
│ password    BLOB  (AES-256-GCM 加密存储) │
│ extra       BLOB  (JSON加密: 安全问题/备注等) │
│ url         TEXT               │
│ updated_at  TEXT               │
└────────────────────────────────┘
```

#### 加密方案（Rust 侧）

1. **主密钥派生**：主密钥 = `Argon2id(用户主密码 + 随机盐)`
2. **记录加密**：每条记录使用独立 IV，采用 AES-256-GCM 加密
3. **会话管理**：应用启动时验证主密码 → 解锁会话密钥 → 存储于 Rust 内存（`zeroize` crate 保证废弃时清零）
4. **超时锁屏**：5 分钟无操作自动清除内存密钥

## 安全设计

### 认证流程

```
应用启动
    │
    ▼
输入主密码 ──→ Argon2id(密码 + 数据库中的盐)
    │                    │
    │              派生出 256-bit 主密钥
    │                    │
    ▼                    ▼
验证密码正确？  ◄──── 用主密钥尝试解密数据库中存储的验证密文
    │
    ├── 失败 → 拒绝进入，记录失败次数（5次后延迟递增）
    │
    └── 成功 → 主密钥存入 Rust 内存（Arc<Mutex<Option<SecretKey>>>）
                  │
                  ├── 设置 5 分钟定时器，超时 → zeroize 清除 → 锁屏
                  ├── 每次 IPC 调用需要解密数据时 → 从内存取密钥 → 解密 → 返回前端
                  └── 手动锁屏 / 退出 → zeroize 清除
```

### 明文隔离保障

密码明文不会出现在以下位置：

- **SQLite 数据库文件**：全部以 AES-256-GCM 密文形式存储
- **JavaScript 内存**：IPC 返回的解密数据用完即丢弃，不缓存至 Pinia store
- **日志文件**：Rust 侧通过 `#[derive(Zeroize)]` 保证 Debug 输出也不泄露敏感信息

## 备选方案：Electron 实现

若不引入 Rust 技术栈，可采用以下替代方案：

**Electron + Vue 3 + better-sqlite3 + SQLCipher**

| 调整项 | 改动说明 |
|--------|---------|
| 桌面框架 | Tauri → Electron（包体 ~10MB → ~150MB） |
| 加密实现 | Rust 加密 → Node.js crypto 模块（AES-256-GCM 算法相同） |
| 数据库 | SQLCipher → better-sqlite3 的 SQLCipher 编译版 |
| IPC 安全 | contextIsolation: true + preload 脚本暴露有限 API |

**安全降级说明**：

- Node.js 进程可通过 DevTools attach 调试（可配置禁用）
- 内存中的密钥清除严格性不及 Rust `zeroize`
- 个人使用场景下风险可控

## 方案总结

**Tauri 2 + Vue 3 + SQLCipher** 组合具备以下优势：

- 约 10MB 级别安装包
- 银行级加密（Argon2id + AES-256-GCM）
- 现代化 UI 技术栈（Vue 3 + Tailwind CSS）
- 强大的图表能力（ECharts）

Rust 侧代码量较少（加密逻辑 + SQL 查询约 500-800 行），主要开发工作量集中于 Vue 前端。
